Managing a Multi-Service Infrastructure with 90+ Containers

How I designed, built, and currently operate a stable multi-node infrastructure running 90+ simultaneous containers and services — using Proxmox VE, Docker, internal networking, and Nginx as the routing backbone.

Problem

Managing unrelated services on a single machine creates dependency conflicts, resource contention, and zero isolation. As service count grew from 20 to 50 to 90+, a structured and scalable approach became critical to prevent cascading failures.

Solution

  • Dedicated Proxmox nodes by environment type — production, dev, internal tools
  • LXC for lightweight services, KVM for heavier workloads
  • Virtual bridges to strictly isolate service groups
  • Nginx as single external routing entry point by domain
  • Automated PBS nightly snapshots with retention policy
